# Reports

Status: frozen for the wave
Last updated: 2026-11-17

Reports are Typst PDFs produced by the installed `typst` binary. Rust writes a
transient JSON projection, invokes Typst, and keeps the `.typ` source and JSON
next to the PDF for reproducibility. No Typst crate. No YAML.

## Templates

Active templates live in `templates/typst/`:

| Template | Input | Purpose |
|---|---|---|
| `dictionary.typ` | all cases | Class test-case dictionary |
| `case.typ` | one case + all runs + bugs | Case dossier |
| `run.typ` | one run + steps + evidence | Execution sheet |
| `bug.typ` | one bug + evidence | Class bug report |

`templates/typst/lib.typ` holds shared colors, tables, chips, status labels, and
evidence helpers. The class originals stay in `src-elizabeth-tours/tqa/` as
reference; the active templates are Laburo-owned.

## Output

```text
.laburo/reports/<timestamp>-<kind>-<id>/
├── report.pdf
├── report.typ
└── data.json
```

`laburo report <kind> <id>` prints the directory, the PDF path, and the
`typst compile` command used.

## Projection

The JSON shape is the contract between SQLite and Typst. Keep it explicit and
stable:

```json
{
  "meta": {
    "generated_at": "2026-11-17 18:30:00",
    "project": "Elizabeth Tours",
    "version": "0.1.0"
  },
  "case": {
    "id": "TC-001",
    "title": "...",
    "description": "...",
    "module": "...",
    "priority": "high",
    "status": "active",
    "environment": "local",
    "gherkin": "Feature: ...",
    "tags": ["unit", "regression"],
    "steps": [
      {"position": 1, "action": "...", "data": "...", "expected": "..."}
    ],
    "requirements": [{"id": "RF-01", "title": "..."}]
  },
  "runs": [
    {
      "id": "RUN-...",
      "mode": "manual",
      "status": "failed",
      "started_at": "...",
      "ended_at": "...",
      "environment": "local",
      "commit": "",
      "steps": [
        {
          "position": 1,
          "status": "failed",
          "observed": "...",
          "notes": "...",
          "evidence": [
            {"kind": "screenshot", "path": "/abs/path.png", "caption": "..."}
          ]
        }
      ]
    }
  ],
  "bugs": [
    {
      "id": "BUG-...",
      "title": "...",
      "description": "...",
      "steps": "...",
      "actual": "...",

      "priority": 1,
      "severity": 1,

      "status": "open",

    }

```

Evidence paths are absolute in the transient JSON so Typst can load images.
The database keeps relative paths.

## Class mapping

- Test case sheet: design fields + execution fields from `run.typ` / `case.typ`.
- Dictionary: all cases with type, level, module, objective, expected result.
- Bug report: the class fields (ID, title, description, steps, actual, expected,
  priority, severity, environment, attachments, comments).
- Each report includes the type of test (tags), initial date, TC + Gherkin, and
  evidence when present.

## Commands

```bash
laburo report dictionary
laburo report case TC-001
laburo report run RUN-20261117-180000-1
laburo report bug BUG-20261117-1
```

No report is generated by the TUI itself; it calls the same library function.

## Rules

- Missing evidence is shown as a gap; never fabricate it.
- Images are embedded only when the file exists and is a supported format.
- Logs are embedded as monospace text, truncated with an explicit marker.
- Report generation is deterministic for the same data and template commit.
