## CLI

```text
laburo web [--port 3000] [--host 127.0.0.1] [--open]
laburo run batch --tag smoke --type functional --level system --status active \
                 --mode auto --driver minitest [--dry-run]
laburo email send --to ... --subject ... --report <path> [--body ...]
laburo case set-automation <id> --mode manual|single|composed [--target <test>]
laburo link add <source-kind> <source-id> <target-kind> <target-id> \
                --relation reproduces [--note ...]
laburo link list <kind> <id>
laburo link remove <link-id>
```

`run batch`:
- Select with `CaseFilter` (tag/type/level/status).
- For each case, create a run using the requested mode (default the case's
  `default_mode`).
- `auto`: run the case-level `driver_target` or step targets through Minitest;
  skip `manual-required` cases with a summary entry.
- `manual`/`dry-run`: create the runs and stop.
- Print a batch summary; do not abort the whole batch on one failure.

## MCP quality gate

`src/ai/check_in.rs` (or `src/quality.rs`):

```rust
pub struct CheckInFilter { pub q: Option<String>, pub case: Option<String>, pub tag: Option<String> }
pub struct CheckIn {
    pub status: String,        // pass | warn | fail
    pub score: i64,            // deterministic 0..100
    pub matched_cases: i64,
    pub automated_cases: i64,
    pub manual_cases: i64,
    pub failing_runs: Vec<String>,
    pub open_bugs: Vec<String>,
    pub evidence_gaps: Vec<String>,
    pub next_actions: Vec<String>,
}
pub fn check_in(conn: &Connection, filter: &CheckInFilter) -> Result<CheckIn>;
```

Rules:
- fail: any failing/error run for a matched case, or an open bug with
  severity 1–2, or no matched cases.
- warn: manual/unmapped cases, missing evidence on a failed run, stale runs,
  medium bugs.
- pass: otherwise.
- No model call; deterministic. P1 may add a local summary.
